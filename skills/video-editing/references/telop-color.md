# テロップの配色

動画のテロップ、見出し、図解を新規作成・修正するときに使う。目的は「読めること」と「映像全体で色がまとまること」の両立。以下は制作上の既定方針であり、ユーザー指定の配色やブランド規定を上書きするものではない。

## 色を選ぶ順序

1. 実際の素材を見て、テロップ位置の明暗・色数・動き、キャラクターやブランドの主な色を把握する。
2. 通常文字、帯・縁、強調の役割を決め、同じ役割にはシーンをまたいで同じHEX値を使う。任意のパレット名など、スキーマにないキーをプロジェクトJSONへ追加しない。
3. まず白系または暗色の通常文字と、それを支える帯を選ぶ。その後、素材に合う強調色を1色選ぶ。話者・状態の区別が必要なときだけ追加する。
4. レンダーした画面で読めるかと、素材を含めて調和しているかを別々に評価する。数値が良くても不自然な配色は直す。

## 調和の判断

- **色相・明るさ・彩度を分けて考える。** 色相が違うだけでは文字は読みやすくならない。文字と背景は明暗差を確保し、彩度は目立たせたい部分に割り当てる。
- **基本は無彩色に近い土台＋強調1色。** カラフルな画面録画やキャラクターがある場合、すでに素材が多くの色を持つ。テロップにも複数の鮮やかな色を足すと競合しやすい。
- **色の温度と鮮やかさを揃える。** 落ち着いた映像には低彩度の帯と穏やかな強調色、元気な映像には少量の鮮やかな強調色など、意図を揃える。クリーム色の文字には茶系の暗い帯、青白い文字には紺系の帯などから試す。
- **補色は自動的に良い文字色の組ではない。** 高彩度の赤と緑、青と橙などを文字と太い縁に直接隣接させると、競合して見えることがある。片方を小さなアクセントにし、帯や縁を中立色に戻す。
- **縁取りを第二の主役にしない。** 標準は単色の暗い縁。蛍光色の文字＋別の蛍光色の縁、多重縁、強い影を同時に使う構成は、明確な演出意図がある場合に限る。細かい漢字が潰れるほど太くしない。
- **強調の面積を小さくする。** 通常の説明は中立色、短い要点だけ強調色にする。全文が強調色のテロップを連続させない。派手さを求められても、まず大きさ・太さ・余白・表示タイミングで差をつける。
- **色の意味を固定する。** 同じ色をある場面では警告、別の場面では成功に使わない。話者名・記号・文言も併用し、赤と緑などの色差だけに区別を任せない。
- **グラデーションは任意の演出。** 通常の字幕や細い文字には単色を優先。大見出しに使うなら近い色相でまとめ、文字全体で読める明暗差を保つ。虹色で情報の優先順位を作ろうとしない。

## すぐ使える出発点

表はすべて不透明色。各行から一組を選び、通常文字・強調文字ともに同じ行の帯へ載せる。複数行の色を無作為に混ぜない。強調色は帯の上の文字用であり、その色を帯にして通常文字を載せても同じ読みやすさになるとは限らない。

| 雰囲気 | 通常文字 `fill` | 帯 `panel` | 強調文字 `fill` |
| --- | --- | --- | --- |
| 汎用・説明動画 | `#F8FAFC` | `#111827` | `#FCD34D` |
| 冷静・技術解説 | `#F8FAFC` | `#0F172A` | `#67E8F9` |
| 暖かい・親しみ | `#FFF7ED` | `#292524` | `#FDBA74` |
| 明るい・簡潔 | `#172033` | `#F8FAFC` | `#1D4ED8` |

ブランド色が淡くて読みにくい場合は、小さな飾りや線にそのまま使い、文字を中立色にする。許可されていないブランド色の変更はしない。迷う場合は最初の行を出発点にして、強調色だけを素材に合わせて調整する。

## 動画背景での読みやすさ

- 文字の直下に来る背景で判断する。画面全体の平均色や、映像が隠している `scene.background` では判断しない。
- 本スキルの制作目安は文字と背景のコントラスト比 **4.5:1以上**。これはWeb向けWCAGの通常文字の基準を参考にしたもので、動画の適合認証ではない。出力解像度上で文字が大きくても、スマホ再生では小さくなるため、安易に目標を緩めない。
- 比率を計算する場合、sRGB各成分を0〜1にし、`c <= 0.04045` なら `c/12.92`、それ以外は `((c+0.055)/1.055)^2.4` に線形化する。相対輝度は `L=0.2126R+0.7152G+0.0722B`、比率は `(明るいL+0.05)/(暗いL+0.05)`。生のRGB平均や色相差で代用しない。
- 半透明の帯は下の映像と合成された色で評価する。HEXのRGB部分だけから安全とは判断しない。背景が明暗を行き来する場合は、まず不透明な帯を使って安定させる。
- 縁・影だけでは複雑な背景から十分に分離できないことがある。読みにくければ、帯を付ける、帯の透明度を下げる、配置を変える、文字量を減らして大きくする、の順に状況に合う修正を選ぶ。

## Video Makerへの適用

- 色指定ができるテロップは `scene.graphics` の `kind: "text"`。`fill` は文字色、`stroke` は縁色、`panel` は `style: "banner"` の帯色。色形式は `#RRGGBB` または `#RRGGBBAA`（末尾がアルファ）。
- 安定した既定形は `style: "banner"`、不透明な `panel`、単色の `fill`、`stroke_width: 0`。短い強調なら `style: "impact"` に暗い `stroke` を指定し、素材上で縁の見え方を確認する。
- `stroke_width` は画面高さ比。`impact` は実装上、画面高さの約0.004以上の縁が付くため、指定値を小さくするだけでは細くならない。細い縁が必要なら `plain` と明示的な `stroke` を使う。
- 現在、通常の `captions` と `scene.title` の色はレンダラー固定。`captions` に `fill` など未対応の属性を書かない。色付き見出しは `graphics` にする。焼き込み字幕を色付きテロップで置換する場合は、必要に応じて `caption_mode: "sidecar"` でSRTを残し、字幕文・表示時間を維持する。単に強調テロップを足すだけなら通常字幕を消さない。
- 1つのtext graphicには単一の `fill`（または対応するグラデーション）しか指定できない。一部の単語だけ色を変える未対応のマークアップを使わない。短い強調を別graphicに分ける場合は、折り返し・位置・表示時間を実画像で確認する。

以下は `scene.graphics` に入れる1要素の例。位置・寸法は実際のUIと字幕領域に合わせ、時刻は `plan_timeline` の結果に合わせる。

```json
{
  "kind": "text", "text": "ここがポイント",
  "style": "banner", "fill": "#FCD34D", "panel": "#111827",
  "stroke_width": 0,
  "x": 0.1, "y": 0.12, "width": 0.8, "height": 0.14,
  "font_size": 0.055, "start": 0, "end": "scene_end"
}
```

## レンダー後の確認と修正

表示が落ち着いたフレームに加え、表示区間内で最も明るい背景・最も暗い背景・背景が切り替わる箇所を確認する。`extract_frame` で実画像を見て、想定するスマホ等の表示サイズでも読む。サンプル確認だけで全フレームの読みやすさを保証したと言わない。

- 読めるが色がまとまらない → 強調色を1色に戻し、帯と縁を中立色にする。素材の色との競合も見る。
- 特定の瞬間に読めない → その瞬間の背景を確認し、不透明な帯か配置変更で直す。
- 目が疲れる・文字がちらついて見える → 高彩度色どうしの隣接を減らす。動画として再生し、動きと圧縮後の文字の輪郭も見る。
- 縁で漢字が潰れる → 縁を細くするか帯に変更し、文字サイズと文字量も見直す。

配色だけの修正では、原則として文言・尺・音声を維持する。既存の承認済みデザインがある場合は、それを基準に問題のある組み合わせを直す。

## 判断の根拠

- [W3C: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — コントラスト比と文字の読みやすさの参考。動画での実視聴確認は別途必要。
- [W3C: Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) — 色だけで意味を伝えないための参考。

上記以外の色数・温度感・パレットは、この動画編集スキルの制作上の出発点であり、科学的な唯一解や規格ではない。
